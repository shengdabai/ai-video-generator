# VidCraft AI - 待讨论问题与疑问

## 一、核心技术问题

### 1.1 视频生成引擎选择

| 问题 | 选项 | 建议 | 待确认 |
|-----|------|------|-------|
| **首选引擎** | Runway Gen-3 / 可灵 / Pika | 可灵（国内优先）+ Runway（海外） | ⏳ |
| **备选引擎** | 多引擎切换策略 | 建议：首选失败自动切换备选 | ⏳ |
| **自研计划** | 是否长期自研模型 | MVP阶段用API，后期评估自研 | ⏳ |

**需要讨论：**
1. 各引擎的API稳定性和响应时间？
2. 生成质量的一致性如何保证？
3. 是否需要建立引擎质量评估体系？

### 1.2 成本控制

```
单视频成本估算（30秒）：
┌─────────────────────────────────────────────────────────────┐
│  LLM (Prompt增强)    ≈ ¥0.1                                 │
│  视频生成 API        ≈ ¥9-15 (取决于引擎)                   │
│  存储 + CDN          ≈ ¥0.5                                 │
│  ─────────────────────────────────────────────              │
│  总计                ≈ ¥10-16/个视频                        │
└─────────────────────────────────────────────────────────────┘
```

**需要讨论：**
1. 免费用户每月3次是否足够？会不会太少导致流失？
2. 是否需要设置视频生成失败的免费重试机制？
3. 批量生成是否有折扣策略？

### 1.3 视频质量保证

| 问题 | 当前方案 | 风险 | 待讨论 |
|-----|---------|------|-------|
| **生成失败** | 自动重试3次 | 增加成本 | 失败后如何补偿用户？ |
| **质量不达标** | 用户可重新生成 | 用户体验差 | 是否建立自动质量评估？ |
| **内容不符** | 人工审核采样 | 效率低 | AI 自动检测方案？ |

## 三、技术架构问题

### 3.1 服务部署方案

| 方案 | 优点 | 缺点 | 适合阶段 |
|-----|------|------|---------|
| **单体应用** | 开发快，部署简单 | 扩展性差 | PoC |
| **微服务** | 扩展性好，隔离性强 | 复杂度高 | 生产环境 |
| **Serverless** | 按需付费，运维少 | 冷启动慢 | 部分场景 |

**推荐：** MVP 阶段采用精简微服务（3-4个服务），避免过度设计

**需要讨论：**
1. 初期是否直接用微服务还是先单体后拆分？
2. 容器编排用 K8s 还是更简单的方案？

### 3.2 数据安全

| 数据类型 | 安全级别 | 存储方案 | 待确认 |
|---------|---------|---------|-------|
| 用户密码 | 高 | bcrypt 哈希 | ✅ |
| 手机号 | 高 | 脱敏存储 | 存储完整还是脱敏？ |
| 视频内容 | 中 | OSS + CDN | 是否需要加密？ |
| 用户描述 | 中 | PostgreSQL | 是否需要脱敏？ |

**需要讨论：**
1. 用户生成的视频保留多久？
2. 删除账号后数据如何处理？
3. 是否需要支持数据导出（GDPR）？

### 3.3 性能目标

| 指标 | MVP目标 | 生产目标 | 当前评估 |
|-----|---------|---------|---------|
| API响应 | <1s | <500ms | 可实现 |
| 视频生成 | <5分钟/分钟 | <3分钟/分钟 | 取决于引擎 |
| 并发用户 | 100 | 10,000 | 需要压测 |
| 可用性 | 99% | 99.9% | 需要监控 |
